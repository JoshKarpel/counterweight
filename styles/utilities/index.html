    Utilities

    To avoid the tedium of writing out styles explicitly over and over, Counterweight provides a variety of Tailwind-inspired "utility styles". These utilities are pre-defined styles that can be combined to form more complex styles.

    The utilities can be imported from the counterweight.styles.utilities module. We recommend a * import for ease of use:

    from counterweight.styles.utilities import *

    That brings in the utilities, the palette's colors, and the ColorName, Shade and Side types the utility functions take, but not Style, Color or anything else the module itself imports, which come from counterweight.styles.

    Each utility is a Style that sets just a small set of properties. Some are constants (e.g., border_heavy, justify_children_center), and the rest are functions that return one (e.g., gap(n), margin_x(n), pad(n)). Color utilities take a color name and shade, or any color. For example, border_color("rose", 200) returns a Style that sets the border color to rose-200, as does border_color(rose_200), with the palette's constant for that color: 

    from counterweight.styles import Style, CellStyle, Color

border_color("rose", 200) == Style(border_style=CellStyle(foreground=Color.from_hex("#fecdd3")))
border_color(rose_200) == border_color("rose", 200)

    Since they are normal Styles, they can be combined to form more complex styles using the | operator. Here we make a new Style for a rose_200-colored heavy border on the top and bottom sides:

    from counterweight.styles.utilities import *

border_heavy_top_bottom_rose_200 = border_y | border_heavy | border_color("rose", 200)

    Actually giving a name to the new style is optional. We can also use the expression directly in our component:

    from counterweight.styles.utilities import *
from counterweight.components import component
from counterweight.elements import Text


@component
def my_component() -> Text:
    return Text(
        content="Hello, world!",
        style=border_y | border_heavy | border_color("rose", 200),
    )

    Performance Considerations

    If you have an expression like border_y | border_heavy | border_color("rose", 200) in your component, it will be evaluated every time the component is rendered. Merging styles with | does take some time, though it is aggressively cached inside the framework. If you find that this is causing performance issues, you should create the style just once, ideally outside your component (i.e., at module scope), so that it runs only once.

    Colors

    The color utilities draw from Tailwind's color palette when given a ColorName such as "rose" and a Shade from 50 (lightest) to 950 (darkest). Given one color instead, they use it, as Tailwind's arbitrary values such as text-[#fbbf24] do: a Color, such as a palette constant or Color.from_hex("#fbbf24"), one of the terminal colors, or a gradient. text_white and text_black are outside the palette.

    Each utility colors one part of a box. In the box below, every part has its own color, matched by the swatch beside the utility that paints it:

    Terminal colors

    A Color looks the same in every terminal. The terminal's own colors follow the user's theme instead, as the colors of a program run in it do: an IndexedColor is an entry of the terminal's 256-color palette, whose first 16 are the black, red, green, yellow, blue, magenta, cyan and white that themes set, then their bright forms, and TERMINAL_DEFAULT is the terminal's default foreground where it colors text, and its default background where it fills one. These utilities set them in each place the color utilities above do, the *_indexed ones taking a palette index from 0 to 255. Screenshots draw them in DEFAULT_PALETTE, and the defaults as white on black, as the first 16 indexed colors and the defaults are drawn below. In a terminal, they take whatever colors its theme gives them.

    def swatch(index: int) -> Text:
    return Text(style=text_bg_indexed(index) | width(6) | text_justify_center, content=str(index))

    Gradients

    A gradient in a color place maps over the box that place paints unless the gradient names its own box. The color utilities above take one, and these put one in each place too.

    Function Description
    text_gradient(gradient: Gradient) -> Style Color the text with a gradient, which maps over the content box unless it names another box.
    text_bg_gradient(gradient: Gradient) -> Style Color the background behind the text with a gradient, which maps over the content box unless it names another.
    border_gradient(gradient: Gradient) -> Style Color the border characters with a gradient, which maps over the border box unless it names another.
    border_bg_gradient(gradient: Gradient) -> Style Color the background behind the border characters with a gradient, over the border box unless it names another.

    content_gradient(gradient: Gradient) -> Style Fill the whole box with a gradient, under any margin, padding and border colors, which maps over the border box unless it names another.

    Attributes

    The text_* attributes draw the text bold, dim, italic, underlined or struck through, and the border_* ones draw the border characters that way. Each has a not_ form that turns it off when merged over a style that turns it on, such as a style for a selected row that isn't bold, merged over a table's bold one. text_link(uri) makes the text a hyperlink that the terminal opens when it's clicked, and text_link(None) makes it not a link, inside text that is one. They're CSS's font-weight: bold, font-style: italic and text-decoration, with dim, which a terminal draws faint, in place of CSS's lighter weights.

    TEXT_ATTRIBUTES: tuple[tuple[str, Style], ...] = (
    ("text_bold", text_bold),
    ("text_dim", text_dim),
    ("text_italic", text_italic),
    ("text_underline", text_underline),
    ("text_strikethrough", text_strikethrough),
)

EMPHASIS = text_bold | text_italic | text_underline | text_color("amber", 300)


def bordered(utility: str, style: Style) -> Text:
    return Text(content=utility, style=border | border_heavy | border_color("sky", 400) | pad_x(1) | style)

    Overflow, clipping and scrolling

    overflow_hidden, overflow_clip and overflow_scroll clip a box's children (and a Text's own lines) to its padding box, on both axes or, with _x or _y, on one, and overflow_scroll makes the box a scroll container there. clip_to_border lets a child, such as a border title, draw on its parent's border instead, and clip_to_screen lets one, such as a dropdown, escape every clip above it. See Clipping.

    overflow_anchor_none turns off scroll anchoring, and stick_to_end makes a scroll container follow its end, on both axes or, with _x or _y, on one; unstick undoes it.
