    Markdown

    markdown_document renders a Markdown document as a component, which goes anywhere a component does. It handles GitHub Flavored Markdown, and YAML front matter at the top of a document.

    README = """\
# Peaks

The *fourteen* peaks above **8000 m** are all in Asia;
see [the list](https://en.wikipedia.org/wiki/Eight-thousander).

> Because it's there.

- Himalayas
  - Everest
  - Kangchenjunga
- Karakoram
  - K2

| Peak | Height (m) |
|:-----|-----------:|
| Everest | 8849 |
| K2 | 8611 |

```python
tallest = max(peaks, key=lambda p: p.height)
```
"""


@component
def root() -> Div:
    return Div(style=col | pad_x(1), children=(markdown_document(README),))

    • Links, bare URLs, and images are hyperlinks to their destinations. An image is shown as its alt text, since a terminal can't show the image.
    • Fenced code blocks are highlighted as the language their info string names, or shown as written if it names none, or one Pygments doesn't know. Code blocks and tables too wide for the space they're given scroll sideways.
    • Math, between $s within a line or $$s on lines of their own, is shown as written, since a terminal can't typeset it. A dollar sign starts math only by Pandoc's rule, with no space just inside it and no digit right after the closing one, so $5 and $10 stays text.
    • Raw HTML is shown as written.

    • Front matter is shown dimmed and highlighted as YAML. Pass MarkdownStyles(front_matter=display_none) to hide it.
    • A task list item's box takes the place of its bullet, or follows its number.
    • An alert is a block quote with a title, colored by its kind.
    • Footnotes are numbered in the order they're referenced, and their definitions follow the rest of the document.

    Parsing

    markdown_document is a memo component, so it parses its document again only when its arguments change, and keeps what it rendered while it stays mounted, freed when it unmounts. A transcript that renders each message with one parses only the message that changed, however many messages there are, as React apps wrap a Markdown component in React.memo.

    The function it calls, markdown, returns the document's Div of elements, and parses the document each time it's called. Call it to put the elements together with others yourself, under use_memo in a component that renders often.

    Scrolling

    A document is as tall as its content, so one longer than the space it's given runs past the bottom of it. Put it in a scroll container, as a browser puts a page in a scrolling viewport, with scroll_on_keys and scroll_on_wheel to scroll it:

    @component
def scrolling() -> Div:
    # Focused, so the keys reach scroll_on_keys.
    use_focus(auto_focus=True)
    return Div(
        style=col | full | border | border_lightrounded | pad_x(1) | overflow_y_scroll,
        on_input=first(scroll_on_keys(), scroll_on_wheel()),
        children=(markdown_document(README),),
    )

    Wide code and tables

    A code block with lines wider than the space it's given scrolls sideways rather than wrapping them, as GitHub's styles give a pre overflow: auto. markdown puts it in a box with overflow_x_scroll and scroll_on_wheel, so the wheel scrolls it under the pointer:

    INSTALL = """\
Install it with:

```bash
uv add counterweight markdown-it-py mdit-py-plugins pygments
```
"""


@component
def wide() -> Div:
    return Div(style=col | pad_x(1), children=(markdown_document(INSTALL),))


     Install it with:                       

  uv add counterweight markdown-it-py m 


     Install it with:                       

 terweight markdown-it-py mdit-py-plugi

    A table scrolls the same way once its cells have wrapped as narrow as their words allow, as GitHub's styles make a table a block with overflow: auto. Only a sideways wheel scrolls them, such as a tilting wheel or a trackpad's sideways swipe, or the wheel with Shift held, as in a browser. An up or down notch without Shift over one passes on to the scroll container around the document, so the document scrolls as it does anywhere else. Some terminals keep Shift with the wheel for their own scrollback and never report it, so there only a sideways wheel scrolls them.

    Browsers also let Tab focus a scroll container with nothing focusable inside, and the arrow keys scroll it. A code block here isn't focusable, since markdown returns elements, not components that could call use_focus, so only the wheel scrolls it.

    To wrap long lines instead, pass MarkdownStyles(code_block_text=text_wrap_stable).

    Line breaks

    CommonMark joins the lines of a paragraph with a space, so a document's source can wrap wherever its author likes. What people type into a chat is different: GitHub's comments and chat apps keep each line break they type. Pass keeps_line_breaks=True to break the line wherever the source does, as the chat example does for your messages. Here the same message is rendered both ways:

    MESSAGE = """\
on my way
running ten minutes late
save me a seat
"""


@component
def line_breaks() -> Div:
    return Div(
        style=row | gap(2) | pad_x(1),
        children=tuple(
            Div(
                style=col | width(26),
                children=(
                    Text(content=label, style=text_color("slate", 400)),
                    markdown_document(MESSAGE, keeps_line_breaks=keeps_line_breaks),
                ),
            )
            for label, keeps_line_breaks in (("CommonMark", False), ("keeps_line_breaks=True", True))
        ),
    )


     CommonMark                  keeps_line_breaks=True       
 on my way running ten       on my way                    
 minutes late save me a      running ten minutes late     
 seat                        save me a seat

    Styles

    MarkdownStyles holds a Style for each kind of block and a CellStyle for each kind of inline span. A code block and a table are each a box around what they show: code_block and table style the box, which scrolls, and code_block_text and table_grid what's inside it. Pass the fields you want to change, and the rest keep their defaults. A field you pass replaces its default whole, so merge over the default's value to change only part of it, as this document does to recolor its heading, block quote and table without losing their bold, border or wrapping:

    DEFAULTS = MarkdownStyles()

# Each field replaces its default, so these merge over the defaults to change only their colors.
WARM = MarkdownStyles(
    heading_1=DEFAULTS.heading_1 | text_color("amber", 300),
    block_quote=DEFAULTS.block_quote | border_color("amber", 500),
    block_quote_text=DEFAULTS.block_quote_text | text_color("amber", 200).text_style,
    list_marker=text_color("amber", 400),
    table_cell=DEFAULTS.table_cell | border_color("stone", 500),
    code_theme="monokai",
    block_gap=0,
)


@component
def styled() -> Div:
    return Div(style=col | pad_x(1), children=(markdown_document(README, WARM),))

    API

    counterweight.markdown.markdown_document 

    markdown_document(
    source: str,
    styles: MarkdownStyles = MarkdownStyles(),
    keeps_line_breaks: bool = False,
) -> Div

    source, a Markdown document, rendered as markdown renders it, by a component that keeps what it rendered while it stays mounted, and parses the document again only when its arguments change, as a memo component does.

    What it keeps is one document per mounted component, freed when the component unmounts, so a transcript of many messages, or one streaming in, parses only the message that changed.

    counterweight.markdown.markdown 

    markdown(
    source: str,
    styles: MarkdownStyles = MarkdownStyles(),
    keeps_line_breaks: bool = False,
) -> Div

    source, a Markdown document, as a Div of its blocks, drawn with styles.

    Links, bare URLs, and images are hyperlinks to their destinations. Fenced code blocks are highlighted as the language their info string names, or shown as written if it names none or one Pygments doesn't know. Code blocks and tables wider than the space they're given scroll sideways with the wheel. Math and raw HTML are shown as written, too.

    It parses source each time it's called. In a component that renders often, use markdown_document, or call it under use_memo.
