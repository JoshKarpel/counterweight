    use_clock

    use_clock gives a component the time, so it can show a clock, an uptime, or a timer while staying pure. A component that reads the time any other way, such as with datetime.now(), keeps showing the time from whenever it last ran.

    @component
def wall_clock() -> Text:
    tick = use_clock(timedelta(minutes=1))
    return Text(content=f"{tick.now:%H:%M %Z}", style=text_color("amber", 400))


@component
def uptime() -> Text:
    tick = use_clock(timedelta(seconds=1))
    seconds = tick.since_start // timedelta(seconds=1)
    return Text(content=f"Up {seconds // 3600}:{seconds // 60 % 60:02}:{seconds % 60:02}")


@component
def status_bar() -> Div:
    return Div(
        style=row | justify_children_space_between | border | border_lightrounded | pad_x(1),
        children=(uptime(), wall_clock()),
    )

    Ticks

    Each call reads the clock every interval. A component takes a reading when it mounts, and again on its first render after each new tick starts, re-running then if nothing else made it. Every render in between gets the same reading, so re-running the component for any other reason doesn't change what it shows.

    Ticks start at whole multiples of interval on the wall clock, so wall_clock re-runs as the minute turns, along with uptime, rather than a minute after the app started. Components that take a reading in the same frame get the same one, so two clocks on screen never disagree.

    Each tick re-runs the components that read the clock and nothing else, so call use_clock in the component that shows the time, not in one that also renders things that don't change with it. See Performance.

    Time zones

    The app's clock reads the wall-clock time in UTC, so an app shows the same time wherever it runs unless it asks for another zone. Give app a SystemClock with a timezone to read the time in that zone instead:

    await app(status_bar(), clock=SystemClock(timezone=ZoneInfo("America/New_York")))

    Ticks follow the clock's zone too, so an interval of a day ticks at that zone's midnight. Converting a UTC reading with tick.now.astimezone(zone) shows the right time, but its ticks still start on UTC's boundaries: a day-long tick at UTC's midnight rather than the zone's, and an hour-long tick off the zone's hour where it's offset by a fraction of one, such as India's.

    Timing from an event

    since_mount is how long the component has been mounted. To time something from an event, such as a key press, render a component that reads the clock and give it a new key when the event happens, which remounts it and starts its since_mount again from zero:

    @component
def lap_time() -> Text:
    elapsed = use_clock(timedelta(seconds=1)).since_mount
    return Text(content=f"{elapsed // timedelta(seconds=1)} s")


@component
def lap_timer() -> Div:
    laps, set_laps = use_state(1)

    def on_input(event: InputEvent, _: Receiver) -> InputResponse:
        match event:
            case KeyPressed(key=Key.Space):
                set_laps(lambda laps: laps + 1)
                return ()
            case _:
                return None

    return Div(
        style=row | gap(1),
        on_input=on_input,
        children=(
            Text(content=f"Lap {laps}:", style=text_color("slate", 400)),
            # A new key each lap remounts lap_time, so its time since mounting starts again from zero.
            lap_time().with_key(str(laps)),
        ),
    )


    Lap 2: 42 s

    Each press of Space starts the next lap from zero:

    A handler sees the reading from the latest tick, so a time it records, such as the lap time when a lap ends, is up to one interval early. Choose an interval as fine as the precision the time needs. A timer that can be paused and resumed loses up to that much on each pause, since it carries the time recorded at the pause into the next run.

    Pausing

    An interval of None stops the component reading the clock, as a null delay pauses React's useInterval: every render returns the last reading, and the clock never re-runs the component. The render that gives it an interval again takes a fresh reading, so a component that stops reading the clock for an hour doesn't show the time from an hour ago when it starts again. Pause a clock a component reads only while something is moving, such as an animation that has finished, so it costs nothing while nothing moves. The animation hooks pause their clocks that way.

    Why compute from elapsed time?

    Compute whatever changes over time, such as an animation frame or a countdown, from since_mount or since_start. Don't keep a running total in state and add to it each tick:

    @component
def spinner() -> Text:
    frame, set_frame = use_state(0)

    async def step() -> None:
        while True:
            await sleep(0.1)
            set_frame(lambda frame: frame + 1)  # wrong: falls further behind each step

    use_effect(step, deps=())

    return Text(content="|/-\\"[frame % 4])

    Each step counts a full interval, but takes longer: sleep wakes up late, and a render and any other work run before the next step starts. The total falls behind the real elapsed time by a little more each step, and the gap only grows. Measured on an otherwise idle event loop, steps of 10 ms counted 2 seconds when 2.05 had passed. Adding up the real time between steps instead fixes the drift, but anything that misses a step or repeats one, such as an effect that restarts, still breaks the total.

    Elapsed time from use_clock is the difference between two readings of a monotonic clock, so a value computed from it can't drift, however long the component runs:

    @component
def spinner() -> Text:
    frame = use_clock(timedelta(milliseconds=100)).since_mount // timedelta(milliseconds=100)
    return Text(content="|/-\\"[frame % 4])

    It also needs no state or effect, so a tick re-renders once instead of twice.

    Testing

    Pass a FrozenClock to app to fix the time, and move it on with AdvanceClock in the autopilot, so a test or a screenshot doesn't depend on when it runs or how long it takes:

    async def test_the_lap_timer_counts_from_the_last_lap() -> None:
    await app(
        lap_timer(),
        headless=True,
        clock=FrozenClock(datetime(2026, 3, 14, 15, 9, 26, tzinfo=UTC)),
        autopilot=[
            AdvanceClock(by=timedelta(seconds=75)),
            KeyPressed(key=Key.Space),
            AdvanceClock(by=timedelta(seconds=42)),
            Screenshot.to_file(Path("lap-timer.txt")),
            Quit(),
        ],
        check_purity=True,
    )

    API

    counterweight.hooks.use_clock 

    use_clock(interval: timedelta | None) -> Tick
    PARAMETER DESCRIPTION
    interval

    How often the component reads the clock. Ticks start at whole multiples of interval past midnight on the wall clock, in the clock's timezone (for an interval that divides a day), so components reading the clock every second and every minute both re-run as the minute turns. None stops reading it, as a null delay pauses React's useInterval: every render returns the last reading, and the clock never re-runs the component, until a render gives it an interval again, which takes a fresh reading.

    TYPE: timedelta | None

    RETURNS DESCRIPTION
    Tick

    A reading of the app's clock, taken when the component mounts, and again on the first render after each new tick starts, with the component re-running then if nothing else made it. Between those, every render returns the same reading, so the component's output stays a function of its arguments and hooks. Components that take a reading in the same frame get the same one, whatever their intervals.
    RAISES DESCRIPTION
    ValueError

    If interval isn't positive.

    counterweight.hooks.Tick dataclass 

    Tick(
    now: datetime,
    since_start: timedelta,
    since_mount: timedelta,
)

    One reading of the app's clock, which use_clock takes for a component when it mounts and again on its first render in each new tick. Every field comes from the same reading, and every duration is measured on a monotonic clock, so changes to the wall clock don't make them jump.

    now instance-attribute 

    now: datetime

    The wall-clock time, in the clock's timezone: UTC unless the app's clock is given another.

    since_start instance-attribute 

    since_start: timedelta

    How long the app had been running.

    since_mount instance-attribute 

    since_mount: timedelta

    How long the component had been mounted: zero on the reading taken when it mounts.

    counterweight.clock.FrozenClock dataclass 

    FrozenClock(start: datetime)

    A clock that starts at start and moves only when an autopilot moves it, so tests, screenshots and recordings don't depend on when they run or how long they take. AdvanceClock moves it on at once, and Wait and WaitFor let it run in real time while the autopilot waits.

    RAISES DESCRIPTION
    ValueError

    If start has no timezone.

    start instance-attribute 

    start: datetime

    When the clock starts, in the timezone it reads the wall-clock time in.
