    use_ref

    use_ref keeps a mutable box, a Ref, for as long as the component is mounted. Changing ref.current doesn't render anything, which is what sets a ref apart from state: it holds what the component needs to remember but doesn't show.

    Using a ref outside of rendering

    Read and write current in handlers and effects, which run after a render, not while rendering.

    @component
def line_entry() -> Text:
    use_focus(auto_focus=True)
    typed = use_ref(list[str]())
    line, set_line = use_state("")

    def on_input(event: InputEvent, _: Receiver) -> InputResponse:
        match event:
            case KeyPressed(key=Key.Enter):
                set_line("".join(typed.current))
                typed.current.clear()
                return ()
            case KeyPressed(key=key) if len(key) == 1:
                typed.current.append(key)
                return ()
            case _:
                return None

    return Text(
        content=f"Last line: {line}",
        style=border | border_lightrounded | pad_x(1) | text_color("amber", 400),
        on_input=on_input,
    )


    ╭────────────────────────────╮
│ Last line: hello           │
╰────────────────────────────╯

    line_entry collects keys without rendering, and renders only when Enter sets line. Rendering reads line, never typed, so the screen above still shows hello with wor typed since. Typing changes nothing on screen until Enter:

    line_entry shows a ref, not how to take text: it has no cursor or Backspace, and drops pastes. For a field, use use_text_input.

    Refs fit:

    • Values a handler builds up before it sets state, as typed does above.
    • Values a later event needs before the next render, such as where a drag began: a handler sees the state of the render that built it, so an event handled in the same batch as the one that set the state doesn't see the new value.
    • Objects outside the tree, such as a task or a client, that a handler or an effect uses.
    • Something expensive to build once, with a function as the initial value: use_ref(lambda: build_index()) calls build_index only on the first render.

    Not reading or writing a ref while rendering

    A component has to be pure: given the same arguments and hook state, it returns the same element. A ref changes without a render, so it isn't part of that state, and a render can skip a component and keep its previous output.

    Writing a ref while rendering happens once per run, and which renders run a component depends on what else changed:

    @component
def counts_renders() -> Text:
    renders = use_ref(0)
    renders.current += 1
    return Text(content=f"rendered {renders.current} times")

    The count goes up only on the renders that re-run counts_renders, so it says nothing reliable. Count something you can name instead, such as the events a handler saw, in state.

    Reading a ref while rendering shows whatever it held when the component last ran:

    @component
def shows_change(value: int) -> Text:
    previous = use_ref(value)
    text = f"{previous.current} -> {value}"
    previous.current = value
    return Text(content=text)

    Once previous holds value, running shows_change again shows value -> value. Keep the previous value in state, and set it together with the current one.

    Reading current once to start with, such as passing use_ref(lambda: build_index()).current to a child, is fine as long as nothing changes it afterward.

    With check_purity on, the second run of every component gets copies of its refs, so assigning current there leaves the component's refs alone, and a component whose output depends on what a ref held raises ImpureComponent. The copies hold the same objects, so changing the object current holds, such as appending to a list, still reaches the component's ref.

    API

    counterweight.hooks.use_ref 

    use_ref(initial_value: Getter[T] | T) -> Ref[T]
    PARAMETER DESCRIPTION
    initial_value

    the initial value of the ref. It can either be the initial value itself, or a zero-argument function that returns the initial value.

    TYPE: Getter[T] | T

    RETURNS DESCRIPTION
    Ref[T]

    A Ref that holds a reference to the given value.

    counterweight.hooks.Ref dataclass 

    Ref(current: T)

    A mutable box that keeps a value across renders, which use_ref returns, the same box on every render. Changing what it holds doesn't render the component again.

    current instance-attribute 

    current: T

    The value the box holds.
