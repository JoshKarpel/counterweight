    Controls

    Controls are objects that can be returned from an element's on_input handler to instruct Counterweight to take some action during the render loop, such as gracefully quitting the application or playing the terminal "bell" sound.

    A handler returns one control (return Quit()), or a tuple of controls, which Counterweight applies in order (return Bell(), Screenshot.to_file(path)), skipping any None in it, as merge skips None styles. Returning (), a tuple of no controls, says the handler handled the event with nothing more to do, and returning any control or tuple stops the event, as () does (see Events). Code outside a handler, such as an effect, sends controls with use_controls.

    counterweight.controls.Quit dataclass 

    Quit()

    Cause the application to quit.

    The quit occurs at the beginning of the next render cycle, so all other events that are due to be processed in the current cycle will be processed before the application exits.

    counterweight.controls.Bell dataclass 

    Bell()

    Cause the terminal to emit a bell sound.

    The bell occurs at the beginning of the next render cycle, so all other events that are due to be processed in the current cycle will be processed before the sound is played.

    counterweight.controls.SetTitle dataclass 

    SetTitle(title: str)

    Set the title of the terminal window. To set it when the application starts, pass title to counterweight.app.app.

    The title is set at the beginning of the next render cycle, so all other events that are due to be processed in the current cycle will be processed before it changes. Line breaks in the title show as spaces, and other control characters as symbols, such as ␛ for an escape.

    The application saves the title it started with, and restores it when it quits and while it's suspended, on terminals that support xterm's title stack (those that don't keep the last title set). RestoreTitle restores it while the application runs.

    title instance-attribute 

    title: str

    counterweight.controls.RestoreTitle dataclass 

    RestoreTitle()

    Restore the title the terminal window had when the application started, undoing any SetTitle, on terminals that support xterm's title stack.

    The title is restored at the beginning of the next render cycle, so all other events that are due to be processed in the current cycle will be processed before it changes.

    counterweight.controls.Screenshot dataclass 

    Screenshot(
    handler: Callable[[Frame], Awaitable[None] | None],
)

    Take a "screenshot" of the rendered UI, and pass it to the given handler callback function as a Frame, which the handler can encode as an SVG image or as text.

    The screenshot is taken at the beginning of the next render cycle, so all other events that are due to be processed in the current cycle will be processed before the screenshot is taken (but the screenshot will still be of the UI from before the next render occurs!). Every screenshot requested in the same cycle receives the same frame.

    handler instance-attribute 

    handler: Callable[[Frame], Awaitable[None] | None]

    to_file classmethod 

    to_file(path: Path) -> Screenshot

    A convenience method for producing a Screenshot that writes to the given path, encoded according to its suffix: .svg for an SVG image, or .txt for text with ANSI escape codes for colors and styles.

    PARAMETER DESCRIPTION
    path

    The path to write the screenshot to. Parent directories will be created if they do not exist.

    TYPE: Path

    RAISES DESCRIPTION
    ValueError

    If the path's suffix is neither .svg nor .txt.

    to_stream classmethod 

    to_stream(
    stream: TextIO | None = None, ansi: bool = True
) -> Screenshot

    A convenience method for producing a Screenshot that prints the frame as text to the given stream.

    PARAMETER DESCRIPTION
    stream

    The stream to print to. Defaults to sys.stderr.

    TYPE: TextIO | None DEFAULT: None

    ansi

    Whether to include ANSI escape codes for colors and styles.

    TYPE: bool DEFAULT: True

    counterweight.output.Frame dataclass 

    Frame(paint: Paint)

    One rendered frame of the UI, as captured by a Screenshot.

    Encode it with svg or text.

    paint instance-attribute 

    paint: Paint

    svg 

    svg() -> str

    The frame as an SVG image, indented one space per level so that it diffs line by line.

    text 

    text(ansi: bool = True) -> str

    The frame as a grid of characters, one line per terminal row, with spaces for empty cells.

    PARAMETER DESCRIPTION
    ansi

    If True, include ANSI escape codes for colors and styles, which show when the text is printed to a terminal. If False, produce plain characters, useful for layout debugging and tests.

    TYPE: bool DEFAULT: True

    counterweight.controls.Suspend dataclass 

    Suspend(
    handler: Callable[
        [TerminalStreams], Awaitable[None] | None
    ],
)

    Suspend the application while the handler function is running, handing the terminal back to whatever started the application, and taking it again when the handler returns. The handler receives the terminal, as TerminalStreams.

    The application will be suspended (and then resumed) at the beginning of the next render cycle, so all other events that are due to be processed in the current cycle will be processed before the application is suspended.

    handler instance-attribute 

    handler: Callable[[TerminalStreams], Awaitable[None] | None]

    to_shell classmethod 

    to_shell() -> Suspend

    A Suspend that stops the application as a shell job, as Ctrl+Z stops a program in a terminal, so the shell takes the terminal back, until it resumes the application with fg. It's what Ctrl+Z does by default (see unclaimed_keys on counterweight.app.app).

    It stops the application's whole process group, as the terminal's Ctrl+Z does, so whatever started the application and waits on it, such as uv run, stops too, which is what tells the shell to take the terminal back.

    to_program classmethod 

    to_program(
    argv: Sequence[str],
    on_exit: Callable[
        [ProgramOutcome], Awaitable[None] | None
    ] = lambda outcome: None,
    env: Mapping[str, str] = frozendict(),
    clear_env: bool = False,
    cwd: Path | None = None,
) -> Suspend

    A Suspend that runs argv on the application's terminal until it exits, such as a pager or an editor, then calls on_exit with how it exited, or why it couldn't start, before the application takes the terminal back. See run_program for env, clear_env and cwd, and for what Ctrl+C and Ctrl+Z do while the program runs.

    A Suspend that edits the file at path in the user's editor on the application's terminal, then calls on_exit with how the editor exited, or why it couldn't start, before the application takes the terminal back. See edit_file for editor.

    Focus

    These controls move focus, which decides the element that key presses go to. The focus handlers return them for Tab and for presses.

    counterweight.controls.FocusNext dataclass 

    FocusNext(within: Subtree | None = None)

    Move focus to the next visible component in the focus order, in tree order, wrapping from the last to the first. From nothing focused, or from focus outside within, it focuses the first. From a focused component that's out of the focus order (see in_focus_order on use_focus), it moves from that component's place in tree order. It does nothing if within has unmounted or holds no visible component in the focus order.

    within class-attribute instance-attribute 

    within: Subtree | None = None

    The element whose focusable descendants, and itself if it's focusable, focus moves among, usually the subtree of the handler's receiver, or None for the whole tree.

    counterweight.controls.FocusPrevious dataclass 

    FocusPrevious(within: Subtree | None = None)

    Move focus to the previous visible component in the focus order, in tree order, wrapping from the first to the last. From nothing focused, or from focus outside within, it focuses the last. Otherwise it behaves like FocusNext.

    within class-attribute instance-attribute 

    within: Subtree | None = None

    The element whose focusable descendants, and itself if it's focusable, focus moves among, or None for the whole tree.

    counterweight.controls.FocusOn dataclass 

    FocusOn(handle: FocusHandle)

    Focus the component whose use_focus has handle, whether or not it's in the focus order.

    If no component can take focus with handle yet, such as one that mounts in the render a state change beside this control causes, it focuses that component in the next render, before the frame is drawn, as showModal focuses a dialog's field as the dialog opens, unless another control moves focus first. Key presses that arrive before that render still go to the component focused when they arrive. It does nothing if its batch of input causes no render, or no component can take focus with handle after that render either, because it hasn't mounted, has unmounted, is hidden, or is unfocusable.

    handle instance-attribute 

    handle: FocusHandle

    counterweight.controls.ClearFocus dataclass 

    ClearFocus()

    Clear focus, so key presses go to the root component.

    Scrolling

    These controls scroll a scroll container. scroll_on_wheel returns ScrollBy for the wheel, and scroll_on_keys returns ScrollBy for the keys that scroll by a step or a page, and ScrollTo for Home and End. ScrollIntoView brings an element into view in every container above it: moving focus applies it to the newly focused element, use_text_area's handler returns it for the cursor's row, and the autocomplete recipe returns it for the highlighted match.

    counterweight.controls.ScrollTo dataclass 

    ScrollTo(
    target: ElementHandle | Subtree,
    x: int | None = None,
    y: int | None = None,
)

    Scroll the scroll container target names so its offset is x and y, as the web's scrollTo does, leaving an axis given as None where it is. The offset is clamped to the range the container scrolls through, from 0 to its max_offset, so a large y scrolls to the end.

    It applies to the layout of the next render, before that render paints, after anchoring and sticking to the end, and in order with the other scroll controls returned since the last render, so a handler that returns it beside a state change scrolls the content that change lays out. It does nothing if target names no mounted, visible scroll container then.

    target instance-attribute 

    target: ElementHandle | Subtree

    The scroll container, by the ElementHandle passed to its handle, or by the subtree of a handler's receiver.

    x class-attribute instance-attribute 

    x: int | None = None

    y class-attribute instance-attribute 

    y: int | None = None

    destination 

    destination(offset: Position) -> Position

    Where this moves a container scrolled to offset, before clamping.

    counterweight.controls.ScrollBy dataclass 

    ScrollBy(
    target: ElementHandle | Subtree, x: int = 0, y: int = 0
)

    Scroll the scroll container target names by x columns and y rows, as the web's scrollBy does: positive values move toward the end of the content, and negative ones toward its start. The offset is clamped, and the control applied, as ScrollTo's is.

    target instance-attribute 

    target: ElementHandle | Subtree

    The scroll container, named as ScrollTo names it.

    x class-attribute instance-attribute 

    x: int = 0

    y class-attribute instance-attribute 

    y: int = 0

    destination 

    destination(offset: Position) -> Position

    Where this moves a container scrolled to offset, before clamping.

    counterweight.controls.ScrollIntoView dataclass 

    ScrollIntoView(
    target: ElementHandle | Subtree,
    block: ScrollAlignment = "start",
    inline: ScrollAlignment = "nearest",
)

    Scroll each scroll container above the element target names so the element's border box is in view, from the innermost container out, as the web's scrollIntoView does, aligning it as block says vertically and as inline says horizontally, with the web's defaults. On each axis, "start" puts the element's start edge at the start edge of the container's view, "center" its center at the view's center, and "end" its end edge at the view's end edge. "nearest" does whichever of "start" and "end" scrolls least, and doesn't scroll at all if the element is already wholly in view, or covers the whole view. Each offset is clamped to the range its container scrolls through.

    It applies as ScrollTo does, to the layout of the next render, so a handler that returns it beside a state change, such as moving a highlight through a long list, shows the scroll in the same frame as the change. The element target names is the one with that element handle in the next render, so an element handle moved onto a newly highlighted element names the new one. It does nothing if target names no mounted, visible element then, and it stops at an element with clip_to_screen, since no container above that element clips it.

    target instance-attribute 

    target: ElementHandle | Subtree

    The element, named as ScrollTo names a scroll container.

    block class-attribute instance-attribute 

    block: ScrollAlignment = 'start'

    Where to put the element vertically.

    inline class-attribute instance-attribute 

    inline: ScrollAlignment = 'nearest'

    Where to put the element horizontally.
