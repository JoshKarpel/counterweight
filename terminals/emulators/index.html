    Emulators and Pseudo-Terminals

    One-shot commands and embedded terminals are built from two lower layers, which this page covers for code that needs them directly: a pseudo-terminal, which runs a program as a terminal window does and hands back the bytes it writes, and a terminal emulator, which turns those bytes into what the terminal shows. Neither knows about the other, so output recorded ahead of time can be fed to an emulator with no program run, and a program's output can go somewhere other than an emulator.

    Pseudo-terminals need Linux or macOS.

    Pseudo-terminals

    run_pty runs a program on a new pseudo-terminal until it exits, in its own session with the terminal as its controlling terminal, calling on_output with what the program writes, standard output and standard error together. It returns how the program exited (Exited), why it couldn't start (FailedToStart), or that it outran its timeout (TimedOut), and hands out a PtyConnection that writes to the program without blocking and resizes its terminal. Cancelling it hangs the program up, as closing a terminal window does.

    use_pty runs a program while its component is mounted, as a terminal window or a multiplexer's pane does: it starts once its size is positive, resizes the terminal as its size changes, and starts the program again when its argv or environment change. It hangs the program up in the background, so a program slow to exit doesn't hold up the app's rendering.

    Hanging up in the background

    The render loop waits for a cancelled effect to finish before it renders again, and hanging up a program that ignores SIGHUP takes up to two hangup_graces. So use_pty, and use_command for each run, call run_pty in a task of the app's task group and await that task through asyncio.shield, which keeps their effect's cancellation from waiting for it:

    sequenceDiagram
    participant L as Render loop
    participant E as Effect
    participant R as run_pty, in the app's task group

    L->>E: Start the effect
    E->>R: Start run_pty and await it through shield
    alt The program exits, or outruns its timeout
        R->>R: Hang up whatever it left running
        R-->>E: Exited or TimedOut
        E->>E: Set the status, or report the run's outcome
    else Cancelled, by cancel, another run or argv, or unmounting
        L->>E: Cancel, then wait for it to finish
        E->>R: Cancel
        E-->>L: Finished at once
        Note over L: Renders again
        R->>R: Hang up the program, for up to two hangup_graces
        R-->>R: Ends cancelled, with no outcome to return
    end
    Note over L,R: An app that stops waits for every hangup still going

    A program that ends by itself returns its outcome through the effect as usual, but only once run_pty has hung up what it left running. Only that effect waits for it, not the render loop, but a program that exits leaving a background job that ignores SIGHUP reads as running until that job is gone. A cancelled run has no outcome to return: cancel has already made it Cancelled, and another run or argv reports its own.

    Emulators

    An Emulator is fed the bytes a program writes, answers the program's queries through on_reply, and snapshot turns what its terminal shows into an immutable Screen. A snapshot of a terminal that didn't change is the same Screen as before, and rows that didn't change are shared between snapshots, so a canvas drawing one redraws only when it changed. scrolled_off returns the rows that scrolled off the top of the screen since it was last called, for an emulator given a scrollback.

    ScreenView is the Canvas painter that draws a Screen, with its cursor when asked, and Transcript the one that draws everything a program printed.

    Colors

    A program's colors reach the app's terminal as the program chose them, so they follow the user's theme as they would had the program run there: a palette color (ESC [ 31 m, or ESC [ 38 ; 5 ; n m) stays an IndexedColor, and an RGB color a Color. A palette entry the program changed (with OSC 4) is the RGB color it changed it to, since the user's terminal doesn't know it.

    A cell in the program's default colors leaves them unset, so it follows the text_style of the canvas showing it. To have those follow the user's theme too, give the canvas the terminal's default colors, as text_terminal_default | text_bg_terminal_default | content_terminal_default (see Terminal colors). A cell whose colors the program swapped (inverse video) or hid (invisible text) has to name its default colors, so it takes the emulator's foreground and background instead, which are white and black unless the program changes them (with OSC 10 and 11). set_default_colors changes them on a running emulator, as the user changing their terminal's theme does, though a color the program set stays what it set.

    Runs argv on a new pseudo-terminal columns by rows, in its own session with the terminal as its controlling terminal, until it exits.

    PARAMETER DESCRIPTION
    on_output

    Called on the event loop with each read of what the program writes, standard output and standard error together, as a terminal shows them.

    TYPE: Callable[[bytes], None]

    on_start

    Called once the program is running, with the connection to write to it and resize its terminal.

    TYPE: Callable[[PtyConnection], None] DEFAULT: lambda connection: None

    env

    Variables to set in the program's environment. The program gets the app's environment (unless clear_env), without COLUMNS and LINES, then TERM=xterm-256color and COLORTERM=truecolor over it, then env over those.

    TYPE: Mapping[str, str] DEFAULT: frozendict()

    clear_env

    Leave out the app's environment, so the program gets only the terminal's variables and env.

    TYPE: bool DEFAULT: False

    stdin

    Where the program reads its standard input from.

    TYPE: StandardInput DEFAULT: 'pty'

    hangup_grace

    How long the program has to exit after each signal that ends it (see below).

    TYPE: timedelta DEFAULT: HANGUP_GRACE

    timeout

    How long the program may run before it's hung up and TimedOut is returned, or None for no limit. Only the program's own run counts against it: once it exits, it has exited, however long reading what it wrote last and hanging up what it left running take.

    TYPE: timedelta | None DEFAULT: None

    RETURNS DESCRIPTION
    Exited | FailedToStart | TimedOut

    How the program exited, why it couldn't start, or that it ran out of time.

    Once the program exits, what it wrote just before is read for up to DRAIN_TIMEOUT. Then, or when cancelled or out of time, the program is hung up, as closing a terminal window does: its process group, which includes anything it started in the background, gets SIGHUP, and whatever is still running hangup_grace later gets SIGTERM, then SIGKILL after another, so no program outlives the call that ran it. Cancelled while hanging up, it sends SIGKILL at once. What the program writes while it's hung up isn't passed to on_output.

    counterweight.pseudoterminal.use_pty 

    use_pty(
    argv: Sequence[str],
    columns: int,
    rows: int,
    on_output: Callable[[bytes], None],
    env: Mapping[str, str] = frozendict(),
    clear_env: bool = False,
    hangup_grace: timedelta = HANGUP_GRACE,
) -> Pty

    Runs argv on a pseudo-terminal while the calling component is mounted, as a terminal window does, with its terminal columns by rows, reading its standard input from the terminal. See run_pty for env, clear_env and hangup_grace, and for how the program is hung up when the component unmounts.

    The program starts once columns and rows are both positive, so a component that sizes the terminal from its own box with use_rects, which is zero on its first render, starts the program at its real size. Later changes to them resize the terminal, which sends the program SIGWINCH, except to a size that isn't positive. A change to argv, env or clear_env hangs the program up and starts it again. Hanging up goes on in the background, so a program slow to exit doesn't hold up the app's rendering, and an app that stops waits for it.

    PARAMETER DESCRIPTION
    on_output

    Called, from the event loop rather than during a render, with each read of what the program writes. The latest render's on_output is the one called.

    TYPE: Callable[[bytes], None]

    counterweight.emulator.Emulator 

    Emulator(
    columns: int,
    rows: int,
    on_reply: Callable[[bytes], None],
    foreground: Color = WHITE,
    background: Color = BLACK,
    scrollback: int = 0,
)

    A terminal emulator columns wide and rows tall, fed what a program writes.

    on_reply receives the bytes the emulator answers the program's queries with (cursor position reports, device attributes), which belong on the program's input, as a terminal would send them. foreground and background are the colors the program's default colors stand for wherever a cell has to name them (see Screen.background), until the program changes them.     Use it as a context manager, or call close, to free the emulator's memory as soon as it's done with.

    scrolled_off 

    scrolled_off() -> Rows

    The rows that scrolled off the top of the screen since the last call, oldest first, or the newest scrollback of them if more did.

    It returns each row once, as it was when it scrolled off, so a program's whole output is what each call returns in turn, followed by the screen. Erasing the scrollback (ESC [ 3 J) doesn't take back rows it already returned, and a program drawing on the alternate screen scrolls nothing off.

    update

    Brings the render state up to date with the terminal, setting aside the rows that scrolled off the screen since the last update, and returns the colors the program's default colors stand for.

    The render state's rows stay dirty until a snapshot cleans them, however many updates come first.

    counterweight.emulator.Screen dataclass 

    Screen(
    columns: int,
    rows: int,
    lines: Rows,
    cursor: Position | None,

    What a program's terminal shows at one moment: its rows of cells, its cursor, its modes and its title.

    Compared by identity: a snapshot of a terminal that changed is a new Screen, and a snapshot of one that didn't is the same Screen as before, so a canvas drawing it draws again only when the program's output changed it. A row the program didn't change is the same tuple as in the previous snapshot.

    columns instance-attribute 

    columns: int

    rows instance-attribute 

    rows: int

    lines instance-attribute 

    lines: Rows

    One row of cells for each of the terminal's rows, each taking exactly columns cells.

    A cell in the program's default colors leaves them unset, so they follow the style of the canvas showing it, and one in a palette color is an IndexedColor, which follows the user's theme, unless the program changed that palette entry (with OSC 4), which makes it the RGB Color the program chose. Where the emulator and counterweight's grapheme_width disagree on how wide a grapheme cluster is, the row keeps the emulator's columns, which the program laid its line out by: a cluster narrower here is followed by spaces, and one wider here, or with no width, is drawn as spaces.

    The colors that the program's default colors stand for wherever a cell has to name them: where the program swapped a cell's colors (inverse video, and the drawn cursor) or made its text the color of its background (invisible text).

    counterweight.painters.terminal.ScreenView dataclass 

    ScreenView(screen: Screen, show_cursor: bool = False)

    A Canvas painter that draws a terminal's screen, with its cursor as a cell with its colors swapped when show_cursor is set, such as while the canvas is focused.

    The box sizes the terminal, not the other way round, so its natural size is zero: size the canvas with its style, and resize the terminal to the canvas's content box. Cells in the program's default colors follow the canvas's text_style, and rows and columns past the box's edges are cut off.
